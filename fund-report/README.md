# 基金配置建議書產生器

比較表列基金，配置後輸出兩份 A4 PDF：**基金比較表**與**客戶建議書**（含配息、本金成長預估，以及一頁給客戶的長期持有叮嚀）。

不需要安裝任何東西。用瀏覽器打開就能用。

---

## 一、怎麼打開

| 方式 | 做法 | 適合 |
|---|---|---|
| 最簡單 | 下載 `standalone.html`，用 Chrome 或 Edge 打開 | 自己用、傳給同事 |
| 完整版 | 下載整個 `fund-report` 資料夾，打開 `index.html` | 要改資料或改版面 |
| 放上網 | 見第七節 | 團隊共用網址，**而且淨值會每天自動更新** |

> 建議用 **Chrome 或 Edge**，輸出 PDF 的版面是以這兩個瀏覽器的列印引擎校正的。

---

## 二、四個分頁

### 1. 基金比較
35 檔基金與 ETF 的淨值、風險等級（RR）、投資方向、前五大持股。

- 色塊按分類篩選，也可以搜尋**基金名稱、投資方向或持股**（打「台積電」會列出所有持有台積電的標的）
- 點欄位標題排序
- 報酬率後面的 `*` 表示該基金成立時間不夠長，該年期沿用了較短年期的數字
- 淨值下方若有橘色**「自動・收盤價」**標記，代表這一檔是每日自動更新的
- **輸出比較表 PDF** — 依分類分頁，每頁最多 8 檔

### 2. 配置試算
改比例數字，右側金額與月配息即時重算。比例不用湊到 100%，系統會按相對比重換算。

**配息處理方式**會明顯改變預估數字，請依客戶實際情況選：

- **配息再投入（總報酬）** — 配息滾回本金，數字最好看，與一般平台的績效表達方式一致
- **配息領出** — 客戶每月實領現金，本金只以「總報酬扣掉配息率」成長，累計已領配息另計。**客戶如果真的按月把錢花掉，要選這個**

### 3. 建議書
螢幕上看到的就是印出來的樣子，共三種頁面：

1. **總覽頁** — 報頭（客戶姓名＋每月可領）、配置一覽、資產成長預估、風險分散度、風險警語
2. **持倉明細** — 各標的前五大持股
3. **長期持有叮嚀** — 給客戶的一頁，見下節

標的多的時候整頁會自動等比縮小，確保剛好一頁、不會多印一張空白紙。

### 4. 資料維護
所有修改只存在**這台電腦的瀏覽器裡**，不會上傳。換電腦要用「匯出／匯入備份 JSON」搬移。

---

## 三、長期持有叮嚀（建議書最後一頁）

這一頁是給客戶看的，內容是八件實務上最常見、最容易讓長期計畫中途夭折的事：

時間比時機更重要 · 帳面虧損不是真的虧損 · 配息不等於獲利 · 定期檢視不是定期更換 ·
別用短期要用的錢投資 · 美元計價部位有兩個變數 · 下跌時的扣款最有價值 · 看得懂才抱得住

底部有「承辦顧問／聯絡方式／下次檢視」三欄可以手寫填。

要改文字的話，打開 `assets/app.js`，找 `LONG_TERM_TIPS` 這個清單，照著格式增刪即可（`<b>…</b>` 會變成橘色粗體）。

## 四、輸出 PDF

按**輸出建議書 PDF** 或**輸出比較表 PDF**，列印視窗跳出來後：

1. 目的地／印表機 → **另存為 PDF**
2. 版面配置 → **直向**
3. 更多設定 → 邊界 → **無**
4. 更多設定 → **勾選「背景圖形」**（沒勾的話橘色和底色會不見）

## 五、淨值每日自動更新 ⚙️

### 會自動更新的（7 檔掛牌 ETF）

`0050`、`006208`、`0056`、`00981A` 走**臺灣證券交易所 OpenAPI**；
`QQQ`、`SPY`、`IVV` 走 **Yahoo Finance**。

每個交易日由 GitHub Actions 抓取後寫進 `data/nav.json`，網站載入時自動套用。
排程是 UTC 22:00（台北隔日早上 6 點），此時台股當日與美股前一交易日都已收盤。

> **注意**：這些是**收盤價**，不是基金公司公告的淨值。ETF 的市價與淨值會有折溢價，
> 介面與報表上都標示為「收盤價」而不是「淨值」。

### 不會自動更新的（其餘 28 檔境外／境內基金）

安聯、聯博、貝萊德、施羅德這類境外基金**沒有可以穩定存取的公開來源**：

- 境外基金資訊觀測站在 GitHub 的伺服器上完全連不上
- 投信投顧公會首頁連得到，但淨值要走查詢頁，不適合當作每日自動化的來源

這些標的請用「資料維護」的**貼上更新**維護。

### 為什麼是伺服器抓、不是瀏覽器抓

實測過了：證交所與 Yahoo 兩個來源都**沒有回傳 `Access-Control-Allow-Origin`**，
瀏覽器的跨網域政策一定會擋下來。所以改成每天在 GitHub 的伺服器上抓好、
存成同網域的 JSON，網站只讀自己的檔案，就完全沒有跨網域問題。

### 前提

自動更新**只在放上 GitHub Pages（或任何網站空間）之後才會生效**。
直接用 `standalone.html` 或本機開檔時，讀到的是打包當下那一份快照，
畫面上的「自動更新狀態」會誠實告訴你目前是哪一種。

## 六、資料哪些是真的、哪些是假設 ⚠️

| 欄位 | 性質 | 來源 |
|---|---|---|
| 掛牌 ETF 的收盤價 | 市場實價 | 證交所／Yahoo，每日自動 |
| 其餘基金的淨值、淨值日 | 公告事實 | 2026/08/10 版比較表，需手動維護 |
| RR 風險等級 | 公告事實 | 同上（不同通路可能略有差異）|
| 投資方向、前五大持股、持股日 | 公告事實 | 最近一期公開月報／ETF 每日持倉 |
| **年化配息率** | **假設值** | 內建預設，**必須自行核對** |
| **各年期年化報酬率** | **假設值** | 內建預設，**必須自行核對** |

**年化配息率**決定建議書上的「每月可領」，**各年期年化報酬率**決定「5 年／10 年後資產」。
這兩欄是內建的合理預設值，不是官方公告數字。介面上有虛線底線的數字都是假設值。

**提供給客戶之前，請到「資料維護」分頁依最新月報或平台資料覆寫這兩欄。**

## 七、放到 GitHub Pages

1. 這個 repo 的 **Settings → Pages**
2. Source 選 **Deploy from a branch**，分支選 `main`，資料夾選 `/ (root)`
3. 等一兩分鐘，網址是 `https://<你的帳號>.github.io/<repo 名稱>/fund-report/`

**每日自動更新的排程，只有在 workflow 檔進到 `main` 分支之後才會開始跑**
（GitHub 的排程只認預設分支）。合併前可以到 Actions 分頁手動按 **Run workflow** 測試。

## 八、更新資料的兩種方式

### 快速：貼上更新
從 Excel 或平台複製後貼進「批次更新」方框，一行一檔：

```
安聯收益成長 AMg7	8.8629	2026/08/11	9.5
富蘭克林穩定月收益	9.98	2026/08/11	5.8
```

欄位順序是 **名稱、淨值、淨值日、年化配息率**，用 Tab 或逗號分隔，後兩欄可省略。
名稱只要包含得到就會對上。找不到的會在下方提示，不會安靜跳過。

### 逐筆：直接編輯表格
下方表格可逐欄改淨值、淨值日、RR、配息率與各年期報酬率，改完自動存檔。

## 九、要加新基金

打開 `assets/funds.js`，複製一整段 `{ ... }` 改內容，欄位說明寫在檔案最上面。
改完如果有用 `standalone.html`，重新產生一次：

```bash
python3 build-standalone.py
```

## 十、技術說明

- 純 HTML + CSS + JavaScript，**沒有任何外部套件或 CDN**，離線可用
- 圖表是自己畫的 SVG，列印不會糊掉
- 主色為暖橘，中性色帶褐調；圖表配色通過色盲辨識度檢驗，深淺色模式各自校正
- 建議書的紙張樣式固定為淺色，切到深色介面也不會印出深色底

```
fund-report/

└── assets/

```

### 預估模型

各年期**分別**採用該年期的年化報酬率，而不是套用單一固定報酬率：

```
第 N 年資產 = 投入本金 × (1 + 該投資組合第 N 年年化報酬率)^N
```

投資組合的第 N 年年化報酬率＝各標的該年期年化報酬率，依配置比例加權。

選「配息領出」時，本金部位改以（總報酬率 − 年化配息率）成長，累計已領配息另外累加。

實際投資決策請洽專業人員並詳閱公開說明書。
